# matter-wake 설계 문서

설계의 기준 문서입니다. 표시 규칙은 다음과 같습니다.

- ✅ 확정: 개발자가 명시적으로 결정한 것. 결정한 날짜를 함께 적습니다.
- 🔶 추천: 에이전트의 추천안. 개발자 결정을 기다립니다.
- 🧪 가설: 프로토타입에서 조정할 값. 데이터나 설정에 두고 코드에 박지 않습니다.

## 1. 게임 개요

- 🔶 픽셀 재질 상호작용과 채굴·건축을 결합한 독자적인 2D 게임. 모든 셀이 떨어지고, 흐르고, 타고, 부서지는 재질이며, 플레이어는 그 안을 파고 짓습니다.
- 장르 세부(목표, 진행 구조, 전투 유무), 채굴 도구의 규칙, 건축 단위, 지지·붕괴 규칙은 아직 정하지 않았습니다. 정할 때 이 절에 추가합니다.

## 2. 기술 스택

- ✅ 2026-11-06: 게임 전체를 Go로 작성하고 Ebitengine으로 그립니다.
  - Rust 코어도 검토했으나, 같은 셀 규칙을 실측했을 때 Go가 네이티브보다 1.4~1.5배 느린 수준에 그쳐 언어를 하나로 유지하기로 했습니다(근거: references.md 2절).
- ✅ 2026-11-06: 출시 대상은 Windows, macOS, Linux 데스크톱. 브라우저(wasm) 빌드는 하지 않습니다.
- ✅ 2026-11-06: 강체 물리는 공식 Box2D v3.2를 저장소에 포함해 cgo로 컴파일합니다(로드맵 4단계에서 도입).
  - shim 없이 C API를 직접 부를 수 있고, 실행 파일 하나로 배포됩니다.
  - 대안이었던 box2d-go(순수 Go 번역)는 같은 장면에서 C보다 1.5~2.8배 느렸습니다(근거: references.md 3절).
- ✅ 2026-11-06: 품질 도구는 golangci-lint v2(gofumpt, goimports 포함)와 govulncheck를 `tools.mod`에 고정해 씁니다. 편집 즉시 포맷하는 Claude Code 훅과 3개 OS CI를 둡니다.

## 3. 시뮬레이션 구조

- 🔶 60Hz 고정 틱. Ebitengine `Update` 한 번에 `game.Step` 한 번.
- 🔶 틱 단위로 결정적입니다. 같은 시드와 같은 입력이면 worker 수와 OS에 상관없이 같은 결과가 나옵니다.
  - ✅ 2026-11-06: 셀 로직은 정수만 씁니다. 속도처럼 소수가 필요한 값은 고정소수점으로 둡니다. float는 Apple Silicon Mac에서 곱셈·덧셈이 FMA로 합쳐져 OS마다 결과가 갈라질 수 있고(pitfalls.md), 정수 쪽이 셀도 작습니다.
  - 난수는 (시드, 틱, 청크)로 정한 스트림에서 뽑습니다.
- 🔶 셀 하나 = 논리 화면의 픽셀 하나.
- 🔶 64×64 청크의 행을 아래에서 위로 차례로 갱신하고, 한 행은 짝수 열과 홀수 열 2단계로 나눠 병렬 실행합니다. 한 셀 갱신이 청크 밖 옆으로 닿는 거리는 `world.MaxReach`(31) 이하이고, 위쪽으로는 쓰지 않습니다.
  - Noita 방식(x·y 홀짝 4그룹)을 먼저 써 봤으나, 경계 위쪽 청크가 아래쪽보다 먼저 갱신될 때 떨어지는 덩어리가 가로 줄무늬로 찢어졌습니다. 그룹 순서를 틱마다 섞어도 오히려 줄무늬가 덩어리 전체로 퍼졌습니다.
  - 대가: 1024×1024 전체 활성 벤치마크에서 8 worker 기준 0.76ms → 1.48ms(단계 수 4 → 32). 1 worker는 4.1ms → 3.7ms. 3단계에서 최적화합니다.
  - 위로 올라가는 재질(기체)은 위에서 아래로 도는 별도 단계가 필요합니다(4단계).
- 🔶 재질 ID는 16비트(최대 65,536종). 셀 하나는 8바이트(재질 2, 색조 1, 마지막 갱신 틱 4).
- 🔶 셀 교환은 즉시 일어나고, 아래 행부터 위로, 행마다 무작위 방향으로 훑습니다. 같은 틱에 두 번 갱신하지 않도록 셀마다 마지막 갱신 틱을 기록합니다.

## 4. 재질

- 🔶 재질은 `data/materials.json`에 정의합니다. 코드는 재질 이름으로 분기하지 않고 종류(kind)와 수치로만 동작합니다.
- 🔶 종류: empty(빈 공간), static(움직이지 않음), powder(떨어지고 쌓임), liquid(떨어지고 옆으로 퍼짐).
- 🧪 현재 재질 값(`data/materials.json`):
  - sand: 밀도 30, 낙하 가속 0.25, 가라앉기 25%, 미끄러짐 80%
  - water: 밀도 20, 낙하 가속 0.375, 가라앉기 50%, 흐름 속도 0.9, 감쇠 0.8, 틱당 최대 4칸. 낙하 가속·흐름 속도·감쇠는 Noita 물의 실제 값을 변환한 것입니다(2026-11-06, [액체 참고 요약](briefs/liquid-flow.md)).
- 🔶 이동 규칙(2026-11-06, Noita 관측 규칙 C47·C49를 참고해 독자 구현, 대응은 references.md, 액체는 [참고 요약](briefs/liquid-flow.md)):
  - 낙하: 떨어지는 동안 속도가 낙하 가속만큼 붙고, 속도 v에서 1칸 + (v−1)을 2로 나눈 만큼 더 내려갑니다. 추가로 내려가는 동안 가끔 옆으로 흩어집니다. 무언가에 부딪히면 속도는 0. 흩어지려던 칸이 막히면 액체는 거기서 멈추고, 가루는 곧장 아래로 다시 시도합니다.
  - 가라앉기: 더 가벼운 액체 속으로는 가라앉기 확률로만 들어갑니다. 빈 칸으로는 항상 들어갑니다.
  - 액체 흐름: 액체는 옆으로 미는 힘을 셀에 저장합니다.
    - 아래가 막혀 있고 한쪽만 열려 있으면 미는 힘을 그쪽으로 흐름 속도만큼 키웁니다. 양옆이 모두 열려 있거나 모두 막혀 있으면 그대로 둡니다.
    - 힘이 1 이상인 동안 한 칸씩 흐르고, 칸마다 감쇠를 곱합니다. 막히면 멈추지만 힘은 남습니다.
    - 떨어진 그 틱에도 내려간 자리에서 이어서 흐릅니다.
    - 방향을 기억하므로 흐름 가장자리가 좌우로 떨리지 않습니다.
  - ✅ 양옆이 모두 열린 액체는 미는 힘을 키우지 않습니다. Noita 관측 규칙과 같습니다(개발자 결정, 2026-11-06).
    - 그래서 평평한 바닥의 물 한 칸은 제자리에 있습니다.
    - 대가: 다르게 두는 안보다 부은 물이 높게 쌓이고(더미 13 → 25칸, 모래는 63칸) 웅덩이가 늦게 평평해집니다(39 → 132틱, 수정 전 94틱).
    - 평탄화는 액체끼리 부딪힐 때의 위쪽 재배치(C50)를 구현할 때 다시 봅니다.
  - 미끄러짐: 아래가 막힌 가루는 미끄러짐 확률로 대각선 아래로 내려갑니다(쌓이는 각도). 액체는 내려가지도 옆으로 흐르지도 않았고 미는 힘이 1 미만일 때만 대각선으로 내려갑니다. 방향은 무작위이고, 미끄러진 쪽으로 미는 힘이 1이 됩니다.
- 🧪 이동 한계: 낙하 속도 최대 12칸/틱, 저장되는 미는 힘 최대 8. 한 셀 갱신이 청크 밖으로 닿는 거리를 `MaxReach` 안에 두기 위한 값이기도 합니다. 액체는 떨어진 틱에도 흐르므로, 낙하 흩어짐(최대 6칸)과 틱당 가로 칸 수를 더한 거리가 `MaxReach` 이하여야 합니다(`world.New`가 검사).
- 🔶 셀 크기 12바이트(재질 2, 색조 1, 마지막 갱신 틱 4, 낙하 속도 2, 미는 힘 2). 테스트가 크기를 고정합니다.
  - 대가: 1024×1024 전체 활성 벤치마크에서 1 worker 3.8ms → 7.5ms, 8 worker 1.5ms → 2.2~2.6ms. 셀이 커진 것과 더 많이 움직이는 것이 합쳐진 값입니다. 셀 휴면(로드맵 1단계)이 평상시 비용을 줄입니다.
  - 액체 규칙을 C49에 맞춘 뒤(2026-11-06): 1 worker 7.7ms → 10.9ms, 8 worker 2.5ms → 2.9ms. 물이 떨어지면서도 옆으로 흐르고 막혀도 미는 힘을 잃지 않아 움직임이 늘어난 비용입니다. 이전 물 값으로 재도 10.4ms라, 대부분 규칙에서 옵니다.
- 불, 기체, 반응, 온도는 로드맵 4단계에서 정합니다.

## 5. 조작 (샌드박스용 임시)

- 🧪 왼쪽 클릭: 선택한 재질 놓기(빈 칸에만). 오른쪽 클릭: 파기(모든 재질 제거). 1~3: sand / water / stone 선택.
- 🧪 브러시 반경 4셀.
- 🧪 월드 크기 480×270, 창 배율 2.

## 6. 미결정 사항

로드맵에서 해당 단계에 도달하면 개발자 결정이 필요합니다.

- 픽셀 셀과 건축 단위의 크기 관계
- 유체/압력 모델의 수준 (비교 대상: The Powder Toy의 4×4 픽셀 압력·공기 속도 격자, references.md 4절)
- 지지·붕괴 규칙
- 파괴 조각을 강체로 만들지, 셀로 흩을지의 기준
- 목표 하드웨어와 성능 예산(최소 사양 CPU, 활성 셀 수)
