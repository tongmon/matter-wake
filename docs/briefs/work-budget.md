# 틱당 작업 예산 참고 요약

작성: 2026-11-07 · 관련 작업: `perf/load-scene`

## 범위

- 이번 변경이 다루는 메커니즘: 한 틱에 돌릴 청크를 고르는 일. 깨어 있는 청크가 훑을 셀이 예산보다 많으면, 카메라에서 먼 청크를 다음 틱으로 미룹니다.
- 함께 읽은 연관 메커니즘(mechanics.md의 Related):
  - 휴면과 깨우기: MATERIAL_TICK 2·4절, PRIORITY_RESULTS 2절, C09, C25, C47, C49, C51
  - 셀 tick, 병렬 그룹: C33, C122
  - 스트리밍: WORLD_STREAMING, C43
  - 셀 생성·로드·저장·작업 선택: CELL_LIFECYCLE_STREAMING(C130). 개발자 요청으로 2026-11-07에 공백 일곱 개를 추가 분석한 문서입니다.
- 모델 `native_probe_sleep_wake`는 카운터를 45 이하로 낮추는 함수 하나만 시험합니다. 선택 규칙의 모델은 없습니다.

## 증상 재현

로드 직후 장면(design.md 2절)이 기준 CPU 추정 셀 예산 8 ms를 넘습니다.

- `BenchmarkLoadScene`(2 worker, 이 PC, 시작 위치에서 60틱 기다린 뒤): 블록을 올리는 틱 6.2 ms, 그 뒤 틱 3.8 ms. 기준 CPU 추정으로는 15.6 ms와 9.6 ms입니다.
- 원인(임시 계측, 저장소 밖):
  - 60틱 뒤 깨어 있는 청크 약 190개가 틱마다 셀 약 37만 개를 훑습니다. 움직이는 셀은 약 1.8만 개입니다.
  - 임시 지형의 동굴에 떠 있는 모래와 물 주머니가 블록이 들어오면서 떨어지기 때문입니다.
- 비교 측정(임시 코드, 2 worker):
  - 블록을 잠든 채로 올리면 0.01 ms와 0.002 ms입니다. C130에 따르면 Noita와 다른 동작이라 버렸습니다.
  - 떠 있는 재질을 없앤 지형에서는 3.5 ms와 0.002 ms입니다.

## 실제 수치

재질 값을 쓰지 않습니다. Noita의 예산 값은 문서에 주소로만 나오고 수치가 없습니다(C130:177). 기준 부하는 로드 직후 작업 영역 최대 약 127개, 중앙값 32개입니다.

## 채택 / 변경 / 제외

- **그대로 씀**
  - 블록이 들어오면 블록 전체를 한 번 훑습니다. 떠 있는 재질은 그때 떨어집니다. (Noita 관측)
  - 후보가 예산보다 많으면 카메라 중심에서 가까운 청크부터 돌리고, 나머지는 갱신 사각형을 지닌 채 미룹니다. (Noita 관측)
  - 화면 밖 청크도 예산 안에서는 돕니다. (Noita 관측)
- **바꿔서 씀**
  - 예산의 단위: Noita는 작업 영역 수를 셉니다. 우리는 훑을 셀 수, 곧 청크 갱신 사각형 넓이의 합을 셉니다. 청크마다 사각형 크기가 크게 달라서(1줄에서 64×64까지) 셀 수가 시간에 더 가깝습니다. (자체 설계)
  - 예산 값: Noita는 시간에 따라 바뀌는 예산도 씁니다. 우리는 고정한 셀 수(🧪)를 씁니다. 결과가 실행 속도와 worker 수에 따라 달라지면 안 되기 때문입니다. (자체 설계)
  - 거리의 기준: Noita의 "카메라 쪽 사각형 중심" 대신, 입력의 카메라가 보는 화면의 중심을 씁니다. 거리는 청크 중심까지의 제곱 거리입니다. (Noita 관측을 우리 입력에 맞춤)
- **쓰지 않음**
  - 순환 재검사와 11번째 갱신: 우리 청크 휴면은 결과가 매 틱 모두 훑은 것과 같아 필요 없습니다.
  - 블록을 재질과 색만 저장하기: 정확히 이어 가기 위해 셀 필드를 모두 저장합니다.

## 측정 (2026-11-07)

references.md 6절 "틱당 작업 예산"에 표가 있습니다.

- 250,000셀에서 로드 직후 장면이 기준 CPU 추정 셀 예산 8 ms 안에 듭니다.
  - 가장 무거운 틱: 3.08 ms × 2.5 = 7.7 ms
  - 블록을 올리는 틱: 1.36 ms × 2.5 = 3.4 ms
- 대가로, 블록이 들어온 뒤 201틱(약 3.4초) 동안 미룬 청크가 있습니다.
- 예산 안의 샌드박스와 붕괴 장면은 동작이 그대로입니다. 골든도 그대로입니다.

## 검증 계획

- **테스트**
  - 예산이 넉넉하면 예산이 없을 때와 매 틱 체크섬이 같습니다.
  - 예산을 넘으면 카메라에서 가까운 청크만 돌고, 먼 청크는 셀이 그대로이며 갱신 사각형을 지닙니다.
  - 화면 가까이가 계속 예산을 넘어도 먼 청크가 정해진 틱 안에 돕니다.
  - 예산이 있어도 worker 수와 상관없이 같은 결과입니다.
  - 할당 0회입니다.
  - 리플레이 형식에 예산을 기록합니다.
- **측정값과 기준**
  - `BenchmarkLoadScene`과 `BenchmarkCollapseScene`(2 worker × 2.5)이 셀 예산 8 ms 안에 드는지
  - 로드 직후 장면이 다 가라앉는 데 걸리는 틱 수가 얼마나 늘었는지
- **골든**
  - 샌드박스 골든과 샌드박스 리플레이 골든은 그대로여야 합니다. 예산을 넘지 않기 때문입니다.
  - 지형 골든은 예산을 넘는 틱부터 바뀔 수 있습니다.
- **직접 플레이로 볼 점**
  - 멀리 이동한 직후, 화면에서 먼 곳의 모래와 물이 늦게 움직이는 것이 거슬리는지
  - 화면 가까이는 그대로인지
