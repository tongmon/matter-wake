## 1단계: 셀 시뮬레이션과 채굴

개발자 결정: 채굴 도구의 동작(속도, 재질별 경도, 파낸 재질의 행방).

- [x] 액체 움직임 개선(C49 참고, 2026-11-06): 낙하 속도, 흐르던 방향을 기억하는 가로 운동량과 감쇠, 고정소수점, 셀 크기 12바이트와 성능 측정
- [x] 부은 물이 모래처럼 쌓이는 문제 수정(2026-11-06, [참고 요약](briefs/liquid-flow.md)): 액체 낙하·가로 흐름 규칙을 C49 모델과 줄 단위로 맞추고 Noita 물 값 적용. 웅덩이 평탄화가 느린 점(132틱)은 플레이에서 문제가 되면 따로 설계
- [x] 액체끼리 부딪힐 때의 위쪽 재배치(C50): 구현하지 않기로 정리(2026-11-06, 개발자 결정). Noita의 섞인 4그룹 순서에서 생기는 충돌을 정리하는 장치라, 아래부터 청크 행을 돌리는 우리 순서에서는 거의 발생하지 않음(references.md "C50을 구현하지 않는 이유"). 스케줄러를 바꾸면 다시 검토
- [x] 모래 움직임 개선(C47 참고, 2026-11-06): 낙하 가속과 여러 칸 이동, 미끄러짐 확률(쌓이는 각도), 액체 속으로 확률적으로 가라앉기
- [ ] 모래 부착과 낙하 중 정지 확률(C47)
- [ ] 여러 액체의 층 분리: 옆으로도 밀도 교환(예: 물 위에 뜨는 기름). 액체를 두 종류 이상 넣을 때 필요
- [ ] 튀는 액체 입자(C81~C84): 세게 부딪히거나 폭발에 맞은 액체 셀을 잠시 입자로 바꿔 날렸다가 격자에 다시 넣기. Noita 물의 생동감을 만드는 큰 요소
- [ ] 셀 휴면: 자리를 잡은 셀의 갱신 생략(MATERIAL_TICK 4절, PRIORITY_RESULTS 2절 참고). 청크 단위 휴면은 2단계
- [ ] 재질별 경도와 채굴 도구 규칙
- [ ] 파낸 재질을 인벤토리로 회수하고 다시 놓기(셀 보존)
- [ ] 바뀐 청크만 업로드하는 렌더링
- [ ] 리플레이 파일 녹화·재생과 리플레이 골든 테스트
- [ ] Ebitengine `exp/vmhost` 기반 렌더 테스트(`tools/vmtest`)

통과 기준: 파고 놓기를 반복해도 셀 수가 보존되고, 리플레이가 3개 OS에서 같은 골든을 냅니다.

## 3단계: 성능 측정

개발자 결정: 목표 하드웨어(최소 사양)와 프레임 예산.

- [ ] Noita 최대 부하 수준 장면(64×64 영역 약 127개 전부 활성 + 강체 300개 + 렌더링)에서 프레임 시간 측정
- [ ] 저사양 CPU에서 측정
- [ ] pprof 프로파일링 플래그
- [ ] 청크 단계 수 줄이기: 행마다 2단계 대신 비스듬한 파면(chunk (cx, cy)를 단계 `(행 번호) + 2·(cx mod 2)`에 배정)으로 바꾸면 단계 수가 약 절반이 됩니다. 장벽 대기 비용(`internal/sched`)도 측정합니다.

통과 기준: 목표 하드웨어에서 최대 부하 장면이 프레임 예산 안에 들어옵니다.
