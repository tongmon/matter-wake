## 1단계: 셀 시뮬레이션과 채굴

개발자 결정: 채굴 도구의 동작(속도, 재질별 경도, 파낸 재질의 행방).

- [ ] 액체 움직임 개선. 지금은 매 틱 1칸 낙하, 셀마다 새로 뽑는 좌우 방향, 빈 칸으로만 최대 4칸 순간이동이라 흐름 가장자리가 좌우로 떨립니다. Noita 관측 규칙(references.md 1절)을 참고해 독자적으로 구현합니다.
  - 낙하 속도: 떨어질수록 빨라지고 한 틱에 여러 칸 이동
  - 가로 운동량: 흐르던 방향을 셀이 기억하고, 흐름 속도만큼 쌓였다가 감쇠
  - 액체끼리 막혔을 때 위쪽 빈 칸으로 옮겨 넣기(부피 보존)
  - 정수(고정소수점)로 구현하고, 셀 크기 증가에 따른 성능을 측정
- [ ] 모래 움직임 개선(C47 참고): 낙하 가속과 여러 칸 이동, 점성에 따른 대각 미끄러짐 확률(쌓이는 각도), 액체 속으로 확률적으로 가라앉기
- [ ] 셀 휴면: 자리를 잡은 셀의 갱신 생략(MATERIAL_TICK 4절, PRIORITY_RESULTS 2절 참고). 청크 단위 휴면은 2단계
- [ ] 재질별 경도와 채굴 도구 규칙
- [ ] 파낸 재질을 인벤토리로 회수하고 다시 놓기(셀 보존)
- [ ] 바뀐 청크만 업로드하는 렌더링
- [ ] 리플레이 파일 녹화·재생과 리플레이 골든 테스트
- [ ] Ebitengine `exp/vmhost` 기반 렌더 테스트(`tools/vmtest`)

통과 기준: 파고 놓기를 반복해도 셀 수가 보존되고, 리플레이가 3개 OS에서 같은 골든을 냅니다.

## 3단계: 성능 측정

개발자 결정: 목표 하드웨어(최소 사양)와 프레임 예산.

- [ ] Noita 최대 부하 수준 장면(64×64 영역 약 127개 전부 활성 + 강체 300개 + 렌더링)에서 프레임 시간 측정
- [ ] 저사양 CPU에서 측정
- [ ] pprof 프로파일링 플래그
- [ ] 청크 단계 수 줄이기: 행마다 2단계 대신 비스듬한 파면(chunk (cx, cy)를 단계 `(행 번호) + 2·(cx mod 2)`에 배정)으로 바꾸면 단계 수가 약 절반이 됩니다. 장벽 대기 비용(`internal/sched`)도 측정합니다.

통과 기준: 목표 하드웨어에서 최대 부하 장면이 프레임 예산 안에 들어옵니다.
