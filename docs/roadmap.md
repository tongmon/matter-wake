## 1단계: 셀 시뮬레이션과 채굴 ✅ (2026-11-06)

개발자 결정: 채굴 도구의 동작(속도, 재질별 경도, 파낸 재질의 행방). 2026-11-06에 정함(design.md 5절). 시작 인벤토리(빈 인벤토리, 개발용 `-creative`)와 손상을 둘 곳(셀의 전용 2바이트 칸, 셀 16바이트)도 정함.

- [x] 액체 움직임 개선(C49 참고, 2026-11-06): 낙하 속도, 흐르던 방향을 기억하는 가로 운동량과 감쇠, 고정소수점, 셀 크기 12바이트와 성능 측정
- [x] 부은 물이 모래처럼 쌓이는 문제 수정(2026-11-06, [참고 요약](briefs/liquid-flow.md)): 액체 낙하·가로 흐름 규칙을 C49 모델과 줄 단위로 맞추고 Noita 물 값 적용. 웅덩이 평탄화는 시드 80개 중앙값 104틱 → 61~71틱(가끔 약 300틱까지 걸리는 꼬리가 있음, 2026-11-06 재측정)
- [x] 액체끼리 부딪힐 때의 위쪽 재배치(C50): 구현하지 않기로 정리(2026-11-06, 개발자 결정). Noita의 섞인 4그룹 순서에서 생기는 충돌을 정리하는 장치라, 아래부터 청크 행을 돌리는 우리 순서에서는 거의 발생하지 않음(references.md "C50을 구현하지 않는 이유"). 스케줄러를 바꾸면 다시 검토
- [x] 모래 움직임 개선(C47 참고, 2026-11-06): 낙하 가속과 여러 칸 이동, 미끄러짐 확률, 액체 속으로 확률적으로 가라앉기
- [x] 모래 규칙을 C47 모델에 맞춤(2026-11-06, [가루 참고 요약](briefs/powder.md)): 떨어지는 중 쉬기, 첫 낙하 틱 가속 없음, 흩어지다 막히면 멈춤, 막혀도 속도 유지, 쉬는 상태, Noita 모래 값. 대각선 왼쪽 먼저는 맞추지 않고 무작위 유지(개발자 결정)
- [x] 재질별 경도와 채굴 도구 규칙(2026-11-06, design.md 5절, [참고 요약](briefs/digging.md)): 재질마다 등급(`hardness`)과 내구(`hp`), Noita 값 그대로. 도구는 힘·틱당 양·붓 반경. 가루와 고정 재질만 팜. 손상은 셀의 전용 2바이트 칸에 내구 비율로 두고 셀을 따라 움직임(셀 12 → 16바이트, 1024×1024 1 worker +2%)
- [x] 파낸 재질을 인벤토리로 회수하고 다시 놓기(셀 보존)(2026-11-06): 재질별 셀 수 인벤토리, 놓으면 차감, 한도 없음. 리플레이 형식 버전 2(`tool`, `mode` 헤더). 시작 인벤토리는 비어 있고, 개발용 `-creative`가 무한 놓기를 켬. 리플레이 골든이 매 틱 셀 수 + 인벤토리 수 보존을 확인하고, `dig_place_cycle.rpl`이 파고 놓기를 되풀이함
- [x] 채굴 손상 표시(2026-11-06): 손상만큼 셀을 흰색 쪽으로 밝게 그림(최대 약 60% 🧪, design.md 5절)
- [x] 리플레이 파일 녹화·재생과 리플레이 골든 테스트(2026-11-06, design.md 6절): 줄 단위 텍스트 형식 `matter-wake-replay 1`, `-record`·`-replay`, 재생 끝에 종료, 재질 지문이 다르면 경고. `internal/replay/testdata`의 골든이 1·4 worker에서 같고, 매 틱 셀 수가 브러시로 놓고 판 만큼만 바뀌는지 확인. 3개 OS에서 같은 골든인지는 CI가 확인

통과 기준: 파고 놓기를 반복해도 셀 수가 보존되고, 리플레이가 3개 OS에서 같은 골든을 냅니다.

2026-11-06에 충족했습니다. 리플레이 골든이 매 틱 재질마다 셀 수 + 인벤토리 수를 확인하고, CI가 Windows, macOS, Linux에서 같은 골든을 냅니다.

남은 항목은 2026-11-06에 옮겼습니다.

- 셀 휴면, 바뀐 청크만 업로드하는 렌더링, 렌더 테스트(vmtest) → 2단계
- 튀는 액체 입자 → 4단계
- 여러 액체 층 분리, 가루 부착 → 재질을 추가할 때

## 2단계: 큰 월드 ✅ (2026-11-06)

개발자 결정: 월드 크기, 저장 단위. 2026-11-06에 정함(design.md 7절). 16384×16384 고정 월드(🧪), 512×512 블록, 청크 변경 사각형으로 깨우기, 시드로 만드는 시험 지형, WASD 카메라, Noita와 같은 상주 규칙(처음에는 화면 사방 256칸 + 최대 12블록으로 구현했다가 Noita 방식으로 바꿈), OS 사용자 폴더에 저장.

- [x] 건너뛴 셀이 다른 셀을 바꾸지 않게 하기(2026-11-06, design.md 3절): 행의 순회 방향을 청크 난수 스트림 대신 (시드, 틱, 청크, 행) 해시로 정하고, 마지막 갱신 틱은 실제로 움직인 셀에만 기록. 골든 체크섬만 바뀌고 셀 수는 그대로
- [x] 활성/휴면 청크와 깨우기(2026-11-06, design.md 7절, [참고 요약](briefs/chunk-sleep.md)): 청크 변경 사각형, 이웃 청크의 표시는 단계가 끝난 뒤 합침. 건너뛴 결과가 매 틱 모두 훑은 결과와 같은지 체크섬으로 확인. 잠든 1024×1024 월드의 틱 5.70 ms → 0.48 µs, 바쁜 월드 +2~6%
- [x] 바뀐 청크만 업로드하는 렌더링(1단계에서 옮김, 2026-11-06, design.md 7절): 청크 버전으로 바뀐 청크만 칠해서 올림. 이동·삭제 없이 색만 바뀐 셀(손상, 4단계의 그을림)도 그 청크를 다시 올림(CELL_DAMAGE_VISUALS 6절의 수용 기준, `TestWearRaisesChunkVersion`)
- [x] 블록 저장 형식(2026-11-06, design.md 7절, `internal/save`): 버전을 두고 셀 필드를 하나씩 기록. 재질은 이름으로 맞춤, CRC-32. 저장 → 불러오기 → 같은 체크섬, 그 뒤로도 같게 진행. 블록 하나 약 204KB, 쓰기·읽기 각 약 4.8 ms
  - 메모(2026-11-06): 저장 형식에 버전을 두고 셀 필드를 하나씩 기록합니다. 셀 메모리를 그대로 덤프하지 않습니다. 셀 구조가 바뀌어도(예: 12 → 16바이트) 저장 파일이 깨지지 않게 하려는 것입니다.
- [x] 월드를 블록 단위로 두기(2026-11-06, design.md 7절): 블록 표(Noita와 같음), 블록 올리기·내리기, 셀 갱신이 닿을 범위에 상주하지 않는 블록이 있는 청크는 멈춤. 바쁜 틱 +12~13%
- [x] 큰 고정 월드의 로직(2026-11-06, design.md 7절): 시드로 만드는 시험 지형, 카메라를 따라 블록 상주·해제(이때는 화면 사방 256칸, 최대 12블록, 먼 것부터. 뒤에 Noita 방식으로 바꿈), 내린 블록은 메모리 저장소에, 리플레이 형식 3(장면·화면·상주 헤더, 입력의 카메라), 지형 리플레이 골든
- [x] 큰 월드의 화면(2026-11-06, design.md 7절): WASD·방향키 카메라(틱당 4칸, Shift 4배), 카메라 위치로 그리기(청크마다 그림, 바뀐 청크만 올림), `-scene terrain`
- [x] 월드 저장·로드(2026-11-06, design.md 7절): `-save` 폴더(기본 사용자 설정 폴더), 내린 블록과 종료 때 저장, 다시 열면 이어서(월드·틱·플레이어·카메라·메모리에 있던 블록). 저장된 월드에 다른 시드·크기를 섞지 않음. 리플레이·녹화·shots는 디스크를 건드리지 않음
- [x] 블록 경계 끊김 없애기(2026-11-06, design.md 7절): 지형 생성 12.4 → 3.3 ms, 디스크 세션은 블록을 백그라운드에서 미리 읽거나 만들고 뒤에서 씀. 60Hz에서 블록 경계를 넘을 때 최대 틱 47~51 ms → 3.5~5.9 ms
- [x] 상주 규칙을 Noita 방식으로(2026-11-06, design.md 7절, [참고 요약](briefs/streaming.md)): 64칸 격자의 카메라 영역과 가는 방향의 앞쪽 영역을 올리고, 60틱마다 검사해 목표 12블록을 넘으면 가장 먼 블록부터 하나씩 내림. 실제 시간 대신 틱, 블록은 틱 안에서 올림. 세션 형식 2(상주 상태 저장), 리플레이 형식 4

통과 기준: 화면 밖으로 나갔다 돌아와도 상태가 보존되고, 휴면 청크는 틱 비용이 거의 0입니다.

2026-11-06에 충족했고, 개발자가 상주 규칙을 Noita 방식으로 바꾼 뒤의 지형을 직접 플레이해 확인하고 단계를 닫았습니다(2026-11-06).

- 상태 보존: 카메라가 떠났다 돌아오면 블록이 떠날 때 그대로 돌아오고(`TestLeavingAndComingBackKeepsTheBlocks`), 저장했다 다시 열면 계속 간 세션과 매 틱 같습니다(`TestSavedSessionGoesOnTheSame`).
- 휴면 비용: 아무것도 움직일 수 없는 1024×1024 월드의 틱이 5.70 ms에서 0.48 µs가 됐고, 16384×16384 월드에 3×3블록이 올라와 잠들어 있으면 1.3 µs입니다.

남은 항목은 2026-11-06에 옮겼습니다. 둘 다 통과 기준에 들지 않았습니다.

- 셀 휴면, 렌더 테스트(vmtest) → 3단계

## 3단계: 성능 측정 ✅ (2026-11-07)

개발자 결정: 목표 하드웨어(최소 사양)와 프레임 예산. 2026-11-07에 정함(design.md 2절): Noita 최소 사양에 맞추고 기준 CPU는 Intel Core i5-7200U. 기준 CPU에서 최대 부하 장면의 한 틱 전체가 16.7 ms 안, 그중 셀은 8 ms 이하(🧪).

- [x] 최대 부하 장면 두 개와 측정(2026-11-07, design.md 2절): 로드 직후(`terrain_load.rpl`, `BenchmarkLoadScene`)와 붕괴(`-scene collapse`, `BenchmarkCollapseScene`). 셀과 렌더를 잼. 강체는 4단계로 옮김
  - 기준 CPU 추정: 붕괴의 셀 6.2 ms는 예산 안. 로드 직후는 블록을 올리는 틱 20.3 ms, 그 뒤 틱 10.4 ms로 넘음
  - 처음 잰 시작점 장면(128청크가 모두 떨어짐, 기준 CPU 추정 약 27 ms)은 Noita 관측보다 가혹해서 쓰지 않음
- [x] 로드 직후 장면을 예산 안으로(2026-11-07, design.md 3절, [참고 요약](briefs/work-budget.md)): 틱당 작업 예산(Noita 방식, 개발자 결정). 깨어 있는 청크가 훑을 셀이 250,000(🧪)을 넘으면 화면 중심에서 먼 청크를 미룸. 기준 CPU 추정으로 블록을 올리는 틱 15.6 → 3.4 ms, 가장 무거운 틱 7.7 ms. 리플레이 형식 5, 세션 파일 형식 3(청크 상태)
  - 원인: 임시 지형의 떠 있는 모래와 물 주머니가 블록이 들어오면서 떨어짐. Noita도 들어온 블록을 한 번 강제로 훑어 떠 있는 재질을 떨어뜨림(CELL_LIFECYCLE_STREAMING, 개발자 요청으로 2026-11-07에 추가 분석)
  - 대가: 블록이 들어온 뒤 약 3.4초 동안 화면에서 먼 곳이 늦게 움직임. 직접 플레이로 확인 필요
- [x] 프로파일링과 시간 측정 플래그(2026-11-07): `-cpuprofile`로 CPU 프로파일을 쓰고, `-timing`으로 틱·그리기·프레임의 CPU 시간(중앙값, p99, 최대, 16.7 ms를 넘은 프레임 수)을 종료 때 기록. GPU 시간은 들어 있지 않음
  - Windows에서는 `time.Now`가 0.5 ms 단위라 틱 하나를 잴 수 없어서, 성능 카운터로 잼(2026-11-07, pitfalls.md)

통과 기준: 목표 하드웨어에서 최대 부하 장면이 프레임 예산 안에 들어옵니다.

2026-11-07에 개발 PC 추정으로 닫았습니다(개발자 결정, design.md 2절). 기준 CPU 실기로는 아직 재지 않았습니다.

- 셀 예산 8 ms: 붕괴 장면의 셀 6.2 ms, 로드 직후 장면의 가장 무거운 틱 7.7 ms입니다. 개발 PC에서 worker 2개로 잰 값에 단일 스레드 차이 약 2.5배를 곱했습니다.
- 이 추정에는 캐시 차이(96 MB 대 3 MB)가 드러나지 않습니다. 실기 확인은 4단계의 강체 측정(처음 300개, 2026-11-07에 450개로 바꿈)에 합쳐, 셀·강체·렌더를 합친 한 틱을 한 번에 잽니다.
- GitHub Actions 러너는 CPU를 고를 수 없는 4 vCPU 공유 VM이라 기준 CPU를 대신할 수 없습니다(2026-11-07 확인).

남은 항목은 2026-11-07에 4단계로 옮겼습니다. 모두 통과 기준에 들지 않았습니다.

- 기준 CPU 실기 측정 → 강체 측정에 합침
- 셀 휴면, 청크 단계 수 줄이기 → "실기에서 예산을 넘으면 할 일"
- 렌더 테스트(vmtest) → 4단계

## 4단계: 반응과 강체

개발자 결정: 반응 체계의 범위, 파괴 조각 처리 기준.

- [ ] 불, 기체, 반응, 온도(C24, C52~C57, C61, C62)
- [ ] 점성 재질(C48): 모래 이동을 재사용하면 안 되는 별도 규칙
- [ ] 튀는 액체 입자(C81~C84, 1단계에서 옮김): 세게 부딪히거나 폭발에 맞은 액체 셀을 잠시 입자로 바꿔 날렸다가 격자에 다시 넣기. Noita 물의 생동감을 만드는 큰 요소
